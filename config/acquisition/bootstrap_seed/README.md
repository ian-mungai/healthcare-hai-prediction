# Bootstrap seed

The files a bootstrap run in an empty environment cannot fetch from a publisher or from S3: public captures that only a person could download. Git LFS stores them (`.gitattributes`), except the 34 hospital archives, which are assets of a GitHub release (see below). `scripts/quality/repo_checks.py` declares this folder as the one data folder besides the test fixtures and the dbt seeds. It admits data files there, the 4 AHRQ technical documents (PDF) and no other kind of file (the 34 hospital archives are never committed, so no rule admits them): the writing, front matter and link checks still read the Markdown here. The 16 plan input files (the 12 MMD browser-history captures, the 3 MMD reference files and `county_adjacency2010.txt`) are in the folder, so a host build reads them from the code archive. The 50 HUD and WONDER manual-unit originals are not added yet. The 10 AHRQ files are added after the build. The 34 hospital archives are never in the code archive: the host downloads them from the seed release after each bootstrap starts. The check passes without them unless `--require-files` is set. The bootstrap's manual download and upload steps are the fallback for the 50 HUD and WONDER originals only. An AHRQ unit has no fallback: the host reads its file from this seed alone.

`manifest.json` lists every expected file, the queue it belongs to and a SHA-256 where a tracked source holds one:

| Folder | Files | Digest source |
| --- | --- | --- |
| `mmd_browser_history/` | the 12 MMD browser-history CSV captures (plan inputs) | the comparison report in the bundle |
| `mmd_references/` | `codebook_crosswalk.csv`, `countynames.tsv`, `urban.tsv`, which the MMD collector reads to build its requests and derived CSV files | the MMD plan |
| `structure_history/` | `county_adjacency2010.txt`, a Latin-1 text file | the geography file period seed (`dbt/seeds/geography_file_periods.csv`), whose row for the capture names the file's SHA-256 |
| `manual_units/<snapshot ID>/` | the original of each of the 44 HUD units (its ZIP-COUNTY workbook) and of each of the 6 WONDER units (its text export), as the publisher served it | the HUD plan for the 44 workbooks, the WONDER plan for the 6 originals |
| `manual_units/<snapshot ID>/` (AHRQ) | the file of each of the 10 AHRQ Compendium units: the 2016 `.xls`, five `.xlsx` workbooks and four `.pdf` technical documents, saved by the owner in a browser on Nov 8 2026. The 2018 workbook is a copy without its workstation path element. Three further technical documents are left out | the AHRQ plan (SHA-256, size, origin URL) |
| `manual_units/<snapshot ID>/` (hospital archives) | the ZIP archive of each of the 34 `main-hai-pdc` units: 33 quarterly releases of the CMS hospital theme (2019 to 2026) and the annual 2026 archive, saved by the owner in a browser on Nov 20 2026 | the SHA-256 that each unit's specification records. The files are release assets listed in `release_assets.json` |

An AHRQ unit (mode `ahrq_compendium`) is a seed-only unit. It has no derived file and no earlier capture. The run never requests its URL, so `www.ahrq.gov` is not on the approved hosts file. The host binds the seeded file to the AHRQ plan by SHA-256 and size and captures it as it is. Three cases make only their unit stale: a file absent from the seed, a link instead of a file and a file the plan does not bind. The owner's notice lists the unit. Each unit's specification records when and from where the owner saved the file. The 2018 unit also records the SHA-256 and size of the workbook as saved and the change that made the copy. The plan binds the copy. AHRQ publishes no terms text for these files. Checked on Nov 9 2026: the Compendium 2023 page (`https://www.ahrq.gov/chsp/data-resources/compendium-2023.html`) asks for an internet citation only ("Compendium of U.S. Health Systems, 2023. Agency for Healthcare Research and Quality, Rockville, MD."), the AHRQ disclaimer page has no reuse text and the files carry no copyright, public domain or permission text. No reuse license is inferred. A push of the seed publishes the files. The terms stay an open item: settle them before any publication of AHRQ-derived data. Use rules: the data holds hospital and health-system names only, no persons. A health system is joint ownership or management, not legal ownership. Each vintage reflects systems in its own year or the year before, so read its reference date from the technical document. The plan sets `model_eligible` to false, so no model approval follows from the seed. Three further technical documents that the owner saved (`chsp_linkage_file_tech_doc.pdf`, `2020-hospital-linkage-techdoc.pdf` and `2023-hospital-linkage-techdoc.pdf`) are not seeded: a text stream of each holds a user directory path and the repository is public. They stay in the owner's download folder and have no unit and no plan entry. The release record `config/acquisition/access_releases_20261108.json` is append-only and counts the owner's 13 downloads (6 workbooks and 7 technical documents), so it stays as written: the plan binds 10 of them. The privacy scan refuses a PDF that holds such a path.

A hospital archive unit (mode `hospital_archive`) is a seed-only unit too. The publisher's content delivery network refuses a scripted request for these archives (HTTP 403 from the host and from the Mac), so the run never requests their URL and `data.cms.gov` stays on the approved hosts file only for the other units that use it. The host takes each archive from the seed and captures it as it is, only when its SHA-256 and size equal the ones the unit records, it is a ZIP and its members equal the members its specification lists. The SHA-256 is `receipt_template.expected_sha256` of the specification and the size is the `bytes` of the queue unit. The members are read as capture mode reads them: nested archives are expanded within the shared bounds (2 GiB declared in all) and the operating system packaging files (`__MACOSX` folders and `.DS_Store`) do not count. A mismatch makes only that unit stale and stores nothing. Each unit's specification records when and from where the owner saved the file. For 33 units the digest equals the one the stored receipt of the earlier capture records. The annual 2026 archive is the republished one: CMS replaced it (66,861,725 bytes against 43,570,839 when the queue was frozen), so its digest, size and member list come from the owner's download, taken as published. It now holds five quarterly archives (Feb 25 2026, May 13 2026, Aug 13 2026, Sep 30 2026 and Nov 12 2026) and a manifest, 316 members in all. Every member that was data stays data. The queue flag `original_contains_personal_details:private_owner_only:redacted_derivative_only` stays on these units. No code reads it and the Nov 17 2026 classification made these sources Public. The privacy scan does not read inside an archive and lists each one as unreviewed. The owner's 34 downloads were read member by member, nested archives included. No member holds a user directory path. Read a replacement archive the same way before it is added.

A unit's derived file is not seeded: neither a HUD `crosswalk.csv` nor a WONDER `county_year.csv`. The bootstrap rebuilds it on the host from the original with the unit's contract (the HUD workbook contract or the WONDER export contract) and captures the unit only when the rebuilt file's SHA-256 and size equal the ones the unit's last capture records in `capture_specs.json`, so the unit's completion record matches. A mismatch makes the unit stale and stores nothing. The check recomputes this for every HUD workbook and WONDER original present.

An entry without a digest is pending: add the digest when the file is added. No entry is pending now. The check refuses a present file without a digest, a file with another digest and a file the manifest does not list. The five reference documents and the 16 ACS units are not part of the seed. The ACS units move to the Census API collector. No seed file is pinned in S3.

The 34 hospital archives (578,560,347 bytes) are public assets of one release of this repository, tag `seed-main-hai-pdc-20261120`. The owner ruled out Git LFS, plain Git and the project bucket (decision of Nov 21 2026). Git tracks only `release_assets.json`: for each archive its name, size, SHA-256 and release address (`https://github.com/ian-mungai/healthcare-hai-prediction/releases/download/<tag>/<name>`). The manifest takes each size from the queue unit and each digest from the unit's specification. The check refuses a manifest that differs from them. After each bootstrap the host (`host_inputs.prepare`) downloads every asset that the seed folder lacks through the reviewed transport. Each download stays within 2 GiB. The host checks the size and SHA-256 of each asset. A missing asset, another size or another digest stops the run before any capture request and places no asset. A file already in the seed folder is checked and not downloaded again. GitHub answers a download address with one redirect to `release-assets.githubusercontent.com` (checked on Nov 21 2026). The transport follows only that one hop from an address below the release prefix. It keeps the signed query out of every saved record. The two hosts `github.com` and `release-assets.githubusercontent.com` are on the approved hosts file because the queue holds units whose seed files come from the release. The downloaded archives are untracked (`.gitignore`) and never committed. `python -m scripts.acquisition.build_release_manifest` rebuilds the manifest. Its `--check-files <folder>` option compares a folder of the files with it.

The host run calls the manual-unit handler (`manual_units.run`, from `capture_mode.process`) for the approved manual units of the seed-only modes: the 34 hospital archives and the 10 AHRQ files. The handler checks each seeded file. The normal capture path stores it: `manual_receipt.py` writes its receipt as a manual download (no HTTP status). Then the unit gets its intent, its objects under `raw/` read back by version and its completion record. A unit without a seed file gets a stale record. So does a unit whose file fails its check. The run record lists such a unit (`stale_units` and `missing_units`) and one notice line names it. A unit with a verified earlier capture keeps it and does not fail the run. A unit with no verified capture is `missing`. Any run that lists a missing unit fails its evidence check. A bootstrap that fails it writes no success marker. Before the host copies or expands a seeded file it admits the disk space. The host needs twice the file plus the expansion its directory declares plus 1 GiB of headroom. A refusal is a stale record with the reason `not_enough_disk_space`. So is a disk that fills while the file is staged. The HUD and WONDER units stay listed as `manual_not_attempted`. They wait until their originals are in the seed and their receipts follow their own storage contracts.

```sh
python -m scripts.acquisition.check_baseline_run                 # manifest, queue binding, digests of present files, LFS rule
python -m scripts.acquisition.check_baseline_run --require-files  # also demands every file without a hold
python -m scripts.acquisition.build_seed_manifest                 # rebuild the manifest from the bundle after a reviewed queue change
```

Every file must pass the privacy scan before it is committed. A CI job that does not need the seed does not fetch it through LFS.
